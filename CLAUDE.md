# Polyester Scan — тестирование обозревателя

Читается в начале каждой сессии. Коротко.

## Кто и зачем

- Автор — Snovin, не программист: отвечать по-русски, коротко, простым языком.
- Цель: находить ошибки в обозревателе Polyester Scan (testnet.polyesterscan.com,
  вышел 28.09.2026) и его API, готовить материал для отчётов команде Polyester
  (расчёт на признание к мейннету).
- Основной проект автора — отдельный репозиторий `polyester_bot` (здесь его нет).

## ЗАДАЧА (первая сессия)

1. Разведка: сайт на SvelteKit, данные берёт из своего API. Найти в JS-бандлах
   (`/_app/immutable/...`) адреса API, эндпоинты и параметры. Выписать в
   `docs/api.md`.
2. Написать `scan_probe.py` (Python, только стандартная библиотека или
   requests; без ключей — только публичные запросы). Проверки:
   - поиск: кривой хэш, адрес чужой сети, пустой запрос, очень длинная строка;
   - листание страниц: дубли/пропуски между страницами, крайние значения
     limit/offset (0, отрицательное, огромное);
   - формат сумм (масштаб, десятичные знаки, у REST биржи раньше были
     ошибки ×1000) и времени (секунды/миллисекунды, 1970-01-01, часовой пояс);
   - ссылки на обозреватели исходных сетей: у всех сетей тестовые
     (sepolia.etherscan.io, mempool.space/testnet, nile.tronscan.org...),
     а у Solana — основной `solscan.io`. Проверить на реальной операции,
     ведёт ли ссылка не в ту сеть (нужен ли `?cluster=devnet`).
   Вывод скрипта короткий: по строке на проверку, `ОК` / `ОШИБКА` + сырой
   ответ сервера при ошибке.
3. Итог — `docs/findings.md`: каждое подозрение отдельно, с запросом,
   сырым ответом, что ожидалось и почему это ошибка (со ссылкой на
   документацию, если есть: testnet.polyester.com/docs/...).
4. Коммит по-русски, пуш в main.

## Правила

- Отчёт команде НЕ писать и не отправлять — только собрать находки.
  Автор решает сам.
- Каждое утверждение в находках проверено живым запросом сейчас, с сырым
  ответом. Догадки помечать «не проверено».
- Не нагружать сервер: пауза между запросами, никакого перебора тысячами.
- Разведку вести скриптами с коротким выводом, а не по одному запросу.
- Не хардкодить адреса в куче мест — одна константа BASE в начале скрипта.
- В тексты для Discord никаких ссылок (автомодерация банит за URL).
